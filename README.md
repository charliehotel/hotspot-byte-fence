# Hotspot Byte Fence

**핫스팟 데이터를 지키는 작은 파수꾼.**

Hotspot Byte Fence는 Mac이 Wi-Fi 핫스팟을 통해 사용한 데이터를 메뉴 막대에 표시하고, 설정한 한도에 도달하면 해당 Wi-Fi 연결을 끊는 macOS 앱입니다. 핫스팟마다 사용량과 한도, 매월 갱신일을 따로 관리할 수 있습니다.

[다운로드 및 릴리스](https://github.com/charliehotel/hotspot-byte-fence/releases)

## 주요 기능

- **사용량 확인:** 업로드와 다운로드를 합산해 GB 단위로 표시합니다. 기본 측정 간격은 5초입니다.
- **단계별 표시와 알림:** 목표 사용량의 50%, 80%, 90%에서 상태를 구분하고 알림을 보냅니다.
- **한도 도달 시 연결 해제:** 차단 일시정지가 꺼져 있으면 대상 Wi-Fi의 연결 해제를 시도합니다.
- **프로필 자동 전환:** 등록한 Wi-Fi에 연결하면 해당 프로필로 전환하고 알림을 보냅니다.
- **프로필 관리:** 별칭·한도·갱신일 편집, 순서 변경, 삭제를 지원합니다.
- **환경설정:** 한국어·영어·시스템 기본 언어, 로그인 시 자동 실행, 알림 종류별 켜기·끄기를 지원합니다.
- **업데이트 확인:** 하루 간격으로 공개 최신 릴리스를 확인하고, 사용자가 승인하면 다운로드·설치·재시작합니다.

현재 소스의 버전은 **0.1.2**이며 Wi-Fi 차단 기능을 포함합니다. 설치 대상은 **Apple Silicon Mac(arm64), macOS 13 이상**입니다. 이는 빌드의 최소 요구 사항이며 모든 macOS 버전에서의 동작 검증을 의미하지는 않습니다. 배포 파일의 검증 환경은 해당 릴리스 설명을 확인하세요.

## 사람이 직접 설치하는 경우

### 1. 배포 파일 받기

[Releases](https://github.com/charliehotel/hotspot-byte-fence/releases)의 **Assets**에서 앱 배포 파일을 받습니다. GitHub가 자동 생성하는 **Source code**는 실행할 앱이 아닙니다.

- **ZIP:** 현재 패키징 도구가 생성하는 형식입니다. 파일명은 `HotspotByteFence-<버전>-unsigned.zip`입니다.
- **DMG:** 해당 릴리스에서 함께 제공하는 경우 선택할 수 있습니다. 디스크 이미지를 열고 앱을 응용 프로그램 폴더로 복사하는 방식입니다.

릴리스에 게시된 SHA-256과 다운로드 파일의 값을 비교합니다. 터미널에서 `shasum -a 256 `을 입력한 뒤 다운로드 파일을 드래그하고 Enter를 누르면 값을 확인할 수 있습니다. 값이 다르면 설치를 중단하고 다시 다운로드하세요.

### 2. 응용 프로그램 폴더로 복사하기

ZIP은 Finder에서 더블 클릭해 압축을 풀고 `HotspotByteFence.app`을 **응용 프로그램** 폴더로 옮깁니다. DMG는 열어서 앱을 **응용 프로그램** 폴더로 복사한 뒤 디스크 이미지를 추출합니다. DMG 안에서 앱을 계속 실행하지 마세요.

기존 버전이 있으면 먼저 종료합니다. 수동 교체 전에 기존 앱을 별도 폴더에 보관하면 이전 버전으로 돌아갈 수 있습니다. 평소 업데이트에는 아래의 **업데이트 확인…** 메뉴를 이용할 수 있습니다.

### 3. 로컬 서명 및 실행

현재 ZIP 배포 경로는 Developer ID 서명·Apple 공증을 전제로 하지 않으며, 앱을 복사한 뒤 로컬 ad hoc 서명을 적용합니다. 터미널에서 다음 명령을 순서대로 실행합니다.

```sh
codesign -s - --force --deep /Applications/HotspotByteFence.app
codesign --verify --deep --strict --verbose=2 /Applications/HotspotByteFence.app
open /Applications/HotspotByteFence.app
```

이는 현재 패키징 도구와 앱 내 업데이트에서 사용하는 서명 방식입니다. 검증 명령이 오류를 반환하면 실행을 멈추고 설치 파일과 서명을 확인하세요. 다른 폴더에 설치했다면 명령의 앱 경로를 바꿔야 합니다.

ad hoc 서명은 개발자 신원을 보증하는 서명이나 Apple 공증이 아니며, 서명한 Mac에만 묶인다는 뜻도 아닙니다. DMG로 배포해도 서명·공증 상태가 자동으로 달라지지는 않습니다.

macOS가 실행을 차단하면 앱의 출처를 확인한 뒤 **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 이용하세요. 자세한 절차는 [Apple의 앱 실행 안내](https://support.apple.com/ko-kr/102445)를 참고하세요.

### 4. 권한 허용하기

앱은 Dock 대신 메뉴 막대에서 실행됩니다.

- **위치 서비스:** 현재 Wi-Fi 이름과 식별 정보(SSID·BSSID)를 읽는 데 필요합니다. 허용하지 않으면 등록된 핫스팟을 식별해 측정할 수 없습니다. 앱 메뉴나 **환경설정 → 일반 → 권한**에서 설정을 열 수 있습니다.
- **알림:** 사용량 경고, 프로필 자동 변경, 차단 및 차단 실패 알림에 사용합니다. macOS 알림 권한과 앱 내부의 알림 설정이 모두 켜져 있어야 합니다.

권한을 허용한 뒤, 측정할 핫스팟을 프로필로 등록하세요.

## AI가 대신 설치하는 경우

사용자는 AI에 다음처럼 요청할 수 있습니다.

> https://github.com/charliehotel/hotspot-byte-fence 를 확인하고 내 Mac에 설치해줘.

AI 에이전트는 다음 절차를 따릅니다.

1. `sw_vers`와 `uname -m`으로 macOS 버전과 아키텍처를 확인합니다. 현재 배포 대상은 macOS 13 이상, arm64입니다.
2. 공식 저장소의 공개 릴리스에서 태그, 실제 Assets 파일명, 다운로드 URL, SHA-256을 읽습니다. 버전과 URL을 추측하지 않습니다. 설치 가능한 릴리스가 없으면 그 사실을 알리고 소스 빌드가 필요한지 설명합니다.
3. 자동 설치에는 `HotspotByteFence-<버전>-unsigned.zip`을 우선 사용합니다. 별도의 임시 작업 디렉터리에 내려받고 **압축을 풀기 전에 SHA-256을 실제로 비교**합니다. GitHub API의 `digest`가 `sha256:` 형식이면 해당 값을 이용할 수 있습니다. 확인 가능한 해시가 없거나 값이 다르면 설치를 중단합니다.
4. 압축 목록에서 절대 경로, 상위 디렉터리 이동, 예상하지 못한 심볼릭 링크를 확인합니다. 임시 디렉터리에 압축을 풀고 앱 이름, 번들 ID(`com.copylawbot.hotspotbytefence`), 버전이 릴리스와 맞는지 확인합니다.
5. 실행 중인 앱과 기존 설치 위치를 확인합니다. 업데이트라면 종료 후 기존 앱을 백업하고 교체합니다. 기존 앱을 무조건 삭제하거나 프로필·사용량 저장 데이터를 지우지 않습니다.
6. 설치한 앱에 위의 로컬 서명과 서명 검증 명령을 실행합니다. 설치 폴더에 쓰기 권한이 없으면 사용자에게 경로 또는 권한 문제를 알립니다.
7. 앱을 열고 메뉴 막대에 나타나는지 확인합니다. 위치·알림 권한과 macOS 보안 확인은 사용자가 직접 승인하도록 안내합니다.
8. 설치 버전, 경로, 해시·서명 검증 결과, 사용자에게 남은 권한 설정을 보고합니다. 설치 성공만으로 핫스팟 측정·차단까지 검증했다고 보고하지 않습니다.

Gatekeeper 전체 비활성화, 광범위한 격리 속성 삭제, 임의의 관리자 권한 상승은 설치 절차에 포함하지 않습니다.

다만 macOS가 실행을 차단하면 AI는 차단 사실만 보고하고 끝내지 말고, 사용자가 직접 해당 앱의 실행을 허용할 수 있도록 다음을 안내합니다.

- 공식 배포 파일의 출처와 SHA-256을 확인한 뒤 앱을 한 번 실행하고, **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**에서 해당 앱을 허용하도록 안내합니다. 표시되는 확인 창과 인증은 사용자가 직접 처리합니다.
- 위 방법으로 해결되지 않아 격리 속성 해제를 검토한다면, 먼저 실제 오류 메시지와 설치된 앱의 격리 속성을 확인합니다. 해제가 필요한 이유와 다운로드 파일에 대한 macOS의 실행 보호에 영향을 준다는 점을 설명하고, **확인된 HotspotByteFence.app 경로에만 한정한 명령**을 사용자에게 제시합니다. AI가 직접 실행하려면 해당 조치에 대한 사용자 승인을 받습니다.
- 조치 후 앱을 다시 열어 메뉴 막대에 나타나는지 확인하도록 안내하고, 위치·알림 권한 설정까지 이어서 설명합니다. 악성 소프트웨어 경고나 무결성 검증 실패는 격리 해제로 우회하지 않습니다.

## 프로필 설정

### 새 핫스팟 등록

1. macOS Wi-Fi 메뉴에서 측정할 핫스팟에 연결합니다.
2. 앱 메뉴의 **프로필 → 프로필 등록…**을 선택합니다. 미등록 Wi-Fi에 연결했을 때 표시되는 등록 안내에서도 시작할 수 있습니다.
3. **감지된 Wi-Fi**가 원하는 네트워크인지 확인합니다.
4. **프로필 별칭**, **목표 한도(GB)**, **매월 갱신일**을 입력하고 **등록**을 누릅니다.

별칭은 “내 아이폰”, “출장용 핫스팟”처럼 알아보기 쉽게 정하면 됩니다. 별칭을 바꿔도 실제 Wi-Fi 이름이 바뀌지는 않습니다.

등록한 네트워크에 다시 연결하면 해당 프로필을 자동으로 인식합니다. 네트워크 이름뿐 아니라 Wi-Fi 인터페이스와 BSSID도 확인하므로, 같은 이름이어도 기기의 식별 정보가 바뀌면 **BSSID 승인 필요**가 표시될 수 있습니다. 이때 연결 대상을 확인하고 해당 Wi-Fi를 다시 등록하면 기존 프로필에 식별 정보를 추가할 수 있습니다.

### 편집·순서 변경·삭제

**환경설정 → 프로필 관리**에서 프로필을 선택해 편집하거나 삭제할 수 있습니다. 드래그 또는 위·아래 버튼으로 바꾼 순서는 메뉴에도 반영됩니다. 연결된 프로필에는 **연결됨** 표시가 붙습니다.

메뉴의 사용량 또는 갱신일 항목을 눌러서도 편집 창을 열 수 있습니다. 프로필을 메뉴에서 선택하는 것만으로 Mac의 Wi-Fi 연결이 바뀌지는 않습니다. 측정과 차단은 실제 연결된 등록 네트워크를 기준으로 동작합니다.

프로필 삭제는 해당 설정과 측정 사용량을 삭제합니다. macOS에 저장된 Wi-Fi 설정은 유지됩니다.

## 목표 사용량은 어떻게 정하나요?

목표 한도는 **이 Mac에서 이번 주기에 추가로 사용할 데이터 예산**입니다. 단위는 십진 GB이며, 1GB는 1,000,000,000바이트입니다.

통신사의 전체 데이터 제공량보다 **테더링에 실제로 남아 있는 양**을 기준으로 정하세요. 휴대전화 자체 사용량, 다른 기기의 사용량, 앱을 켜기 전 사용량은 앱에 합산되지 않습니다.

예를 들어 테더링 잔여량이 20GB이고 그중 다른 기기에 5GB를 남겨두려면, 이 Mac의 한도를 15GB 이하로 설정할 수 있습니다. 측정 차이와 연결 해제까지의 지연을 고려해 여유를 더 두어도 좋습니다.

- 숫자를 직접 입력하거나 슬라이더로 조절합니다.
- 집이나 사무실 Wi-Fi처럼 한도 관리가 필요 없는 곳에는 **무제한**을 설정할 수 있습니다. 사용량은 계속 표시하지만 비율은 표시하지 않습니다.
- 이미 측정한 사용량보다 낮게 한도를 변경하면 연결 해제가 실행될 수 있습니다.
- 한도를 바꿔도 이미 측정한 사용량을 0으로 만들지는 않습니다.

| 목표 대비 사용량 | 표시 |
|---|---|
| 50% 미만 | 정상 |
| 50% 이상 | 주의 |
| 80% 이상 | 경고 |
| 90% 이상 | 위험 |
| 100% 이상 | 한도 도달, 차단 일시정지가 꺼져 있으면 연결 해제 시도 |

잠금 아이콘은 한도 도달 상태에서도 표시되므로 아이콘만으로 연결 해제 성공을 판단하지 마세요. macOS의 실제 Wi-Fi 연결 상태와 차단 실패 알림도 확인하세요.

## 갱신일은 언제 사용하나요?

**매월 갱신일**은 데이터 사용량을 새 주기로 집계하는 기준 날짜입니다. 통신사에서 테더링 데이터가 다시 충전되는 날짜에 맞추면 됩니다.

- 매월 1일 충전되는 요금제라면 **1일**을 선택합니다.
- 매월 15일 충전된다면 **15일**을 선택합니다.
- **31일**을 선택하면 31일이 없는 달에는 그 달의 마지막 날을 사용합니다.
- 날짜 경계는 현지 시간의 자정 기준입니다. 앱이 실행 중이며 해당 프로필을 처리할 때 새 주기를 확인하고 사용량을 0으로 집계합니다.

**갱신일을 변경하면 다음 주기 계산부터 새 날짜를 사용합니다.** 저장 자체가 사용량 초기화는 아니지만, 새 기준으로 계산한 주기가 기존 주기보다 뒤라면 곧바로 새 주기로 넘어가 사용량이 초기화될 수 있습니다. 따라서 “다음 달부터만 적용되는 예약 설정”으로 사용하지 마세요.

반대로 새 기준의 주기가 기존보다 앞이면 현재 구현은 시간 역행으로 판단해 시간 조정 확인 상태로 들어갈 수 있습니다. 갱신일은 실제 요금제 기준이 바뀔 때 조정하세요.

## 사용량 초기화 버튼은 언제 사용하나요?

**사용량 초기화…**는 해당 프로필에서 지금까지 측정한 사용량을 즉시 0으로 되돌리는 버튼입니다. 확인 창에서 **초기화**를 눌러야 적용됩니다.

통신사에서 데이터를 새로 충전했는데 앱의 주기와 맞지 않거나, 테스트 측정값을 지우고 실제 측정을 시작하려는 경우에 사용할 수 있습니다. 매월 정상적으로 갱신되는 경우에는 매번 직접 누를 필요가 없습니다.

**이 버튼은 통신사의 실제 사용량·잔여량을 바꾸지 않으며, 갱신일도 변경하지 않습니다.** 같은 통신사 주기 중에 초기화하면 이전 사용량이 앱의 한도 계산에서 빠집니다. 그 경우 한도도 현재 남은 데이터에 맞춰 조정하세요.

추가로 인터넷을 잠깐 사용하려는 목적이라면 사용량을 지우기보다 **차단 일시정지**를 사용하세요. 측정값을 유지한 채 차단을 멈추며, 다시 보호하려면 **차단 재개**를 선택합니다. 일시정지 중에도 데이터는 소모됩니다.

## 환경설정과 알림

**환경설정 → 일반**에서 언어, **Mac 시작 시 자동 실행**, Wi-Fi 위치 권한을 확인할 수 있습니다.

알림은 다음 종류별로 켜고 끌 수 있습니다.

- 프로필 자동 변경
- 네트워크 차단 및 차단 실패
- 목표 사용량 50% 도달
- 목표 사용량 80% 도달
- 목표 사용량 90% 도달

알림을 끄는 것은 차단 일시정지와 다릅니다. 알림 설정을 바꿔도 사용량 측정과 한도 처리는 계속됩니다.

## 업데이트

앱은 실행 중 하루 간격으로 GitHub의 공개 최신 정식 릴리스를 확인합니다. **업데이트 확인…** 메뉴에서 직접 확인할 수도 있습니다. 초안과 사전 릴리스는 자동 설치 대상으로 취급하지 않습니다.

새 버전이 있으면 다운로드 여부를 확인하고, 해시·앱 정보를 검증한 뒤 **설치 및 다시 시작**을 다시 확인합니다. 기존 앱은 교체 중 복구용으로 보관하고, 새 앱의 실행 요청이 성공하면 휴지통으로 옮깁니다. 휴지통 이동에 실패하면 설치 폴더에 백업을 보존합니다. 프로필과 사용량은 유지합니다. 서명 변경으로 위치·알림 권한을 다시 허용해야 할 수 있습니다.

자동 설치는 공식 ZIP과 SHA-256 정보가 있어야 가능합니다. DMG만 제공하는 릴리스에서는 현재 앱의 자동 설치 기능을 사용할 수 없습니다.

## 측정 범위와 한계

- 이 Mac에서 등록한 Wi-Fi 인터페이스를 통해 송수신한 데이터만 합산합니다. 휴대전화 자체나 다른 기기의 데이터는 포함하지 않습니다.
- Wi-Fi 인터페이스 기준이므로 통신사 청구량과 다를 수 있고, 해당 인터페이스의 로컬 네트워크 통신도 포함될 수 있습니다.
- 앱 종료·절전 등으로 측정하지 못한 구간은 사후 복구하지 않습니다.
- 기본 5초 간격의 측정과 연결 해제 지연 때문에 한도를 넘을 수 있습니다. 초과분이 항상 소량인 것은 아닙니다.
- VPN이 대상 Wi-Fi를 통해 보내는 트래픽은 물리 Wi-Fi에서 한 번 계산하며, VPN 가상 인터페이스를 별도로 더하지 않습니다.
- 자동 차단은 대상 Wi-Fi 연결 해제를 수행하는 기능입니다. 통신사 측 데이터 차단이나 모든 네트워크 경로의 차단을 보장하지 않습니다.

## 소스 빌드와 배포 형식

개발에는 Swift 6.3 이상 도구 체인과 macOS SDK가 필요합니다. 저장소 루트에서 실행합니다.

```sh
swift build -c release
python3 Scripts/package-app --binary .build/release/HotspotByteFence
```

현재 패키징 도구는 `dist/`에 앱 번들, `HotspotByteFence-<버전>-unsigned.zip`, `package-summary.json`을 생성합니다. ZIP을 만든 후 로컬 앱 번들에 ad hoc 서명을 적용하므로 ZIP과 로컬 앱의 서명 상태가 다릅니다. 원본 ZIP의 SHA-256은 서명 후 앱 번들의 해시와 비교하지 않습니다.

**DMG 병행 배포안:** 사람에게는 앱과 Applications 바로가기가 들어 있는 DMG를 제공하고, AI 설치와 앱 내 업데이트에는 기존 ZIP을 유지할 수 있습니다. 두 형식은 같은 버전의 앱을 담고, 각각의 다운로드 파일에 대한 SHA-256을 릴리스에 게시해야 합니다. 현재 `Scripts/package-app`은 DMG를 생성하지 않습니다.

자동 업데이트 호환성을 위해 정식 릴리스는 `v0.1.0` 같은 버전 태그와 그에 대응하는 `HotspotByteFence-0.1.0-unsigned.zip` 파일명을 사용해야 합니다. 릴리스 파일의 SHA-256 정보도 필요합니다.

구현 문서와 별개로 실제 배포 파일의 검증 기록은 [Capability Gates](docs/HotspotByteFence_CapabilityGates.md)와 [운영 검증 절차](docs/HotspotByteFence_OperatorRunbook.md)에서 관리합니다.
